# 小vi 白底正文配图

## 核心定位

为中文内容生成 16:9 横版正文配图和轻量 IP 插图。底层方法沿用小黑 Skill 的“角色参与核心动作 + 一个隐喻讲清一个结构”，但视觉角色替换为小vi。

默认角色是“小vi”：圆脸、豆豆眼、长深棕发、Claude Coral 樱桃发夹、奶白荷叶领/裙、粗黑线、平涂色块。她必须参与画面的核心动作，不能只是站在旁边当装饰。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：整体风格、颜色、禁忌。
- `references/xiaovi-ip.md`：小vi 的形象、性格、动作库。
- `references/composition-patterns.md`：适合小vi的构图模式和隐喻方法。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `assets/reference/xiaovi-c2-avatar.png`：角色定稿参考。
- `assets/examples/`：已生成样例，只作风格校准，不要照抄构图。

## 工作流

### 1. 消化内容

先读用户给的正文、链接、截图、Markdown 或简短主题。提炼：

- 核心观点是什么
- 哪个动作或隐喻最能解释它
- 小vi 应该亲手做什么
- 是否需要整组 shot list，还是直接生成单张图

不要平均配图。优先选择认知锚点：提炼特征、整理信息、点亮想法、搭建流程、跑通路径、包装输出、前后对比、常见坑、角色状态变化。

### 2. 先出配图策略

如果用户说“分析怎么配图 / 哪些地方需要配图 / 给 shot list”，先给 3-8 张图的策略。每张写清：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 小vi 正在做什么
- 建议元素
- 建议短标注

### 3. 直接生成图片

如果用户明确说“生成 / 输出 / 做图 / 帮我画 / 做一套图”，不要停下来等确认；用内置 `image_gen` 每张单独生成。不要把多张图拼在一张里，除非用户要求总览图。

每张图必须包含：

- 16:9 横版正文配图
- 纯白背景
- 粗黑或近黑手绘线稿
- 小vi C2 Claude Coral 色调
- 大量留白
- 小vi 作为核心动作主体
- 一张图只讲一个核心结构或隐喻

避免正式 PPT、复杂架构图、商业插画、3D、渐变、阴影、复杂背景、过多文字。

### 4. 检查与迭代

生成后按 `references/qa-checklist.md` 检查。如果出现角色变脸、颜色跑偏、画面太满、背景不是白色、变成 PPT、文字太多、中文错字严重、小vi只是装饰，优先重生成或局部编辑。

### 5. 保存交付

如果用户在 workspace 内工作，把最终图复制到：

```text
assets/<content-slug>-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

如果只是生成个人资产，可保存到当前项目或 `vivi-character-system/<topic>/`。保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

生成后的交付要简短说明：

- 生成了几张
- 每张用途
- 保存路径
- 哪些图最稳，哪些图可选

不要长篇解释风格理论；让图自己说话。
